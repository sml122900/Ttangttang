# 토스 빌링 자동결제 테스트 시 "지원되지 않는 카드 종류" 에러

## 문제상황
`scripts/e2e-flow.mjs`(폰 없이 전체 플로우를 검증하는 헤드리스 E2E 스크립트)의 3단계에서,
구매자 빌링키를 토스의 "인증 없이 카드정보로 발급하는" API(`POST
/v1/billing/authorizations/card`)로 발급받아 accept API의 실제 결제 체인
(`paymentGateway.chargeBilling`)까지 검증하려 했다. `.env`에 임의로 만든 카드번호/유효기간을
넣고 실행하자 두 단계에서 연속으로 막혔다.

1. 1차 실행: `INVALID_CARD_EXPIRATION 카드 정보를 다시 확인해주세요 (유효기간)`
2. 형식을 고친 뒤 2차 실행: `지원되지 않는 카드 종류입니다` (결제 승인 단계, 빌링키 발급 자체는
   성공)

## 시도한 것들
1. **유효기간 형식 의심** — 커뮤니티 예제 코드를 찾아 `cardExpirationYear`가 4자리(YYYY)가
   아니라 2자리(YY), `cardExpirationMonth`가 0으로 채운 2자리(MM)여야 함을 확인. 스크립트에
   `normalizeExpiration()`을 추가해 4자리 연도/패딩 없는 월도 자동 보정하도록 고침 → 1차
   에러는 해결됐지만 2차 에러(`지원되지 않는 카드 종류`)가 새로 나타남.
2. **카드 종류 문제로 좁힘** — 빌링키 "발급"은 성공했는데 "결제 승인"에서만 막힌다는 점에서,
   임의로 만든 카드번호의 BIN(앞자리)이 체크카드/기프트카드류나 자동결제 미지원 카드사로
   해석됐을 가능성을 의심.
3. **토스 공식 문서 확인** (`docs.tosspayments.com/blog/how-to-test-toss-payments`) — 결정적
   문장을 확인: **"테스트용 국내 카드번호는 없어요. 직접 발급받은 카드 정보를 입력해서 결제를
   해도 테스트 환경에서는 실제로 돈이 출금되지 않기 때문에 안심하고 사용해도 괜찮습니다."**
   즉 유효기간·잔액은 부정확해도 승인은 나지만, **카드번호(BIN) 자체는 실존하는 카드사의 번호
   체계여야** 하고, 그마저도 카드사 정책상 일부 카드 종류(체크카드/기프트카드/법인카드 등)는
   자동결제(빌링) 자체가 막혀 있을 수 있다.

## 최종 해결법
근본 원인이 "테스트 환경 설정 문제"가 아니라 "토스 빌링 자체가 임의의 가짜 카드번호로는 검증할
수 없는 상품"이라는 사실로 판명됐으므로, 우회가 아니라 **검증 범위를 재설계**했다.
- `scripts/e2e-flow.mjs`에 `SKIP_CHARGE`(기본값 `true`) 도입 — 매물 등록/지원서 제출/RLS는
  스크립트로 매번 헤드리스 검증하고, 실제 카드 승인이 필요한 결제(charge) 단계는 스크립트에서
  분리. 대신 4단계(messages RLS) 검증에 필요한 `transactions` 행은 service role로 직접
  insert해서 결제 여부와 무관하게 계속 검증 가능하게 함.
- 카드정보를 `scripts/.env`에 평문으로 보관해야 하는 부담도 함께 사라짐 — 실카드로 결제 승인을
  확인하는 건 어차피 실기기에서 토스 결제창 인앱 복귀와 함께 검증해야 하는 항목이라, 그쪽으로
  역할을 넘겼다.
- 상세 설계 판단은 [[e2e-flow-charge-step-separation]] 참고.

## 이력서 소재
"결제 API 연동 테스트에서 마주친 에러를 임의값 조정으로 우회하지 않고 공식 문서 원문까지
확인해 '테스트 전용 카드가 존재하지 않는다'는 제약을 확정한 뒤, 그 제약에 맞춰 자동화
스크립트의 검증 범위 자체를 재설계함(민감정보 평문 보관 회피 + 검증 가능한 부분과 실기기가
필요한 부분을 명확히 분리)."
