# 2026-07-31 — Phase 3: 지원과 돈 (헤드리스 E2E 검증)

## 오늘 한 일

### 1. 폰 없이 돌리는 E2E 스크립트 작성 (`scripts/e2e-flow.mjs`)
- 판매자 로그인 → 매물 등록(pickup_slots 2개) → item_id 확인.
- 구매자 로그인 → item API 응답의 pickup_slots가 등록값과 정확히 일치하는지 검증 →
  지원서 제출 → application_id 확인.
- 판매자 로그인 → applications 목록 조회 → `apps/web`의 실제 accept API(`fetch`)를 호출해
  `accept_application → chargeBilling → finalize_accepted_application` 체인 검증.
- 양쪽 계정으로 messages 삽입/조회 후, 제3자 계정과 anon 클라이언트로 조회(0건이어야 함)와
  삽입(RLS 위반 에러여야 함)을 모두 시도해 §2 RLS 정책(당사자만 허용)을 음성 테스트까지 확인.
- `scripts/.env.example` + 루트 `package.json`에 `pnpm e2e` 스크립트 추가로 재사용 가능하게
  구성.

### 2. 토스 빌링 결제 승인 테스트 중 카드 정보 문제 발견
- 임의로 만든 카드번호로 빌링키 발급/결제를 시도하다 `INVALID_CARD_EXPIRATION` →
  (형식 수정 후) `지원되지 않는 카드 종류입니다` 순으로 막힘.
- 토스 공식 문서를 확인해 "테스트용 국내 카드번호는 없다"는 정책을 확정 — 자세한 원인 추적은
  [[toss-billing-no-dedicated-test-card]].

### 3. 스크립트 검증 범위 재설계 (`SKIP_CHARGE`)
- 실카드 정보를 스크립트 `.env`에 평문 보관하고 싶지 않다는 판단 하에, 결제(charge) 단계를
  분리 가능하게 만듦. 기본값(`SKIP_CHARGE=true`)에서는 accept API를 호출하지 않고, 4단계
  messages RLS 검증용 `transactions` 행은 service role로 직접 생성해서 결제 여부와 무관하게
  계속 돌아가게 함.
- `scripts/.env`에 이미 들어있던 카드 정보 필드는 값을 비웠고, `SKIP_CHARGE=true`로 설정.
- 설계 판단 상세: [[e2e-flow-charge-step-separation]].

### 4. 시크릿 관리 재확인
- `scripts/.env`가 `.gitignore`의 `.env` 패턴(경로 무관 매칭)에 실제로 걸리는지
  `git check-ignore -v` / `git ls-files`로 재확인 — 커밋 이력에도 없음을 확인.

### 5. 최종 검증
- `pnpm web:dev` 기동 후 `pnpm e2e` 실행 — `SKIP_CHARGE=true` 기준으로 1·2·4단계 전부 통과
  (3단계는 결제 부분만 의도대로 스킵, transaction은 service role로 대체 생성).

  땅땅 확정까지 1회 통과 확인 (CLAUDE.md 진행상황 "실기기 1회 E2E" 항목, 여전히 미완료).
