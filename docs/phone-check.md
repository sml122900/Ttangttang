# 실기기 확인 체크리스트

이 저장소 전체에서 "코드는 됐는데 실기기 확인 안 함"으로 남아 있던 항목을 전부 모았다
(2026-09-30 기준). Expo Go로 되는 것과 안 되는 것을 나눠뒀다 — **푸시 알림은 Expo Go가 SDK
53부터 원격 푸시를 지원하지 않아 개발 빌드가 필요하다** (`apps/mobile`에 이미
`expo-dev-client`가 있다).

## 0. 준비

```
pnpm mobile:dev                 # Expo Go로 대부분 확인 가능
# 또는 푸시 알림까지 확인하려면 개발 빌드가 필요 — eas build --profile development
```

- [ ] `apps/mobile/.env`의 `EXPO_PUBLIC_WEB_ORIGIN`이 `https://ttangttang-web.vercel.app`인지
      확인 (ngrok 아님, `docs/decisions/environment-separation.md`)
- [ ] 판매자용 계정 1개, 구매자용 계정 1개 준비(로그인 화면 "다른 방법으로 로그인"의 개발용
      이메일 로그인 사용 가능 — 카카오는 아직 실 키 미설정, 아래 참고)

## 1. Phase 3 — 지원과 돈 (여전히 실기기로 1회도 안 돈 핵심 플로우)

- [ ] **CTA 세이프에어리어**: 등록/상세/지원서 화면 하단 버튼이 제스처 바·노치에 가리지
      않는지 (기기별로 `insets.bottom` 반영 확인)
- [ ] **슬롯 렌더링**: 등록 시 넣은 방문 가능 시간이 지원서 화면에 칩으로 정확히 나오는지
- [ ] **카드 등록 → 인앱 복귀**: 지원서 작성 중 카드 등록 웹뷰(토스 호스팅 화면)를 열고
      등록을 마치면 앱으로 자동 복귀하는지. 특히 **커스텀 탭에서 사용자 제스처 없이 커스텀
      스킴으로 이동하는 게 막히는 기기가 있는지** 확인(막히면 `/pay/billing-done`의 "앱으로
      돌아가기" 수동 버튼이 뜨는지도 같이 확인)
- [ ] **땅땅 더블 노크 모션**: 판매자가 수락할 때 스탬프 애니메이션 + 햅틱 2회가 실제로
      체감되는 타이밍인지(240ms/530ms)
- [ ] **전체 체인 1회**: 카드등록 → 지원 → 수락 → 결제 승인 → 낙찰 확정까지 실카드로 한 번
      끝까지 통과. (`SKIP_CHARGE`류 안전장치는 이제 스크립트에서 제거됐다 — 실기기가 유일한
      실결제 검증 경로다)

## 2. Phase 4 — 신뢰 루프

- [ ] **사진 업로드 + AI 어시스트**: 등록 화면에서 실제로 사진을 찍거나 골라 업로드 →
      AI가 제목/설명/시작가를 채우는지, 실패 시(네트워크 끊기 등) 수동 입력으로 자연스럽게
      넘어가는지. 물건이 아닌 사진(예: 셀카)을 올렸을 때 "AI가 물건을 확인하지 못했어요"
      안내가 뜨고 폼이 비어있는 채로 남는지(2026-09-30 수정분, `apps/web/lib/ai-assist.ts`)
- [ ] **수령시한 선택**: 등록 화면에서 24/48/72시간 중 골라 등록 → 낙찰 후 채팅 배너의
      "OOO까지 수령 확인이 필요해요" 문구가 그 값과 맞는지
- [ ] **수령 확인**: 낙찰 후 채팅에서 구매자·판매자 각각 확인 버튼 → 한쪽만 눌렀을 때 "상대방
      확인 대기" 문구, 양쪽 다 누르면 "거래가 완료됐어요"로 바뀌는지
- [ ] **노쇼 정산**: 수령시한을 아주 짧게(테스트용으로 DB에서 직접 당겨서) 만들어 10분 대기 →
      "노쇼로 정산됐어요" 알림/배너가 뜨는지
- [ ] **푸시 알림 5종 실수신** (개발 빌드 필요): 지원 도착 · 낙찰 · 거절 · 수령임박 · 노쇼정산
      — 실제로 기기에 알림이 오는지. 앱이 백그라운드일 때도 오는지
- [ ] **settings/payment**: 카드 등록 후 설정 화면에 카드사·마스킹 번호가 실제로 표시되는지
      (Toss 응답 필드명을 코드에서 추측으로 처리해둠 — `apps/web/lib/payments/toss.ts`의
      `extractCardInfo` 주석 참고, 틀리면 "등록된 카드"로만 나오고 기능엔 지장 없음)
- [ ] **매물 수정·삭제**: 내 매물 편집 화면 진입 → 시작가 칸이 비활성(회색)으로 보이는지,
      사진 재업로드가 되는지, 삭제 시 대기 중이던 지원자에게 거절 알림이 가는지

## 3. Phase 3 후속 — 설정·계정·온보딩 (3단계)

- [ ] **온보딩 3장**: 첫 로그인 시 자동으로 뜨는지, "현재 위치로 자동 설정" 버튼을 눌렀을 때
      권한 요청이 뜨는지. **카카오 로컬 API 키가 아직 플레이스홀더라 실패할 것으로 예상됨** —
      실패해도 "다른 이름으로 직접 설정" 폴백으로 온보딩을 끝낼 수 있는지가 진짜 확인 포인트
- [ ] **신고·차단**: 매물/지원자/채팅 상대 신고 시트가 뜨는지, 차단 후 그 사람 매물이 피드에서
      바로 사라지는지(새로고침 필요할 수 있음)
- [ ] **계정 삭제**: 설정 > 계정 삭제 → 확인 시트 → 실제로 로그아웃되고 재로그인이 안 되는지
- [ ] **카카오 로그인**: 카카오 개발자센터에 앱을 등록하고 실 키를 채운 뒤에만 확인 가능
      (`supabase/.env`의 `SUPABASE_AUTH_EXTERNAL_KAKAO_CLIENT_ID`가 여전히
      `placeholder_client_id`라면 이 항목은 스킵 — 심사관용 이메일 로그인 경로로 대체 확인)

## 4. 알려진 이슈 (실기기와 무관, 참고용)

- **`expo start --web`이 런타임 에러로 뜨지 않는다**: NativeWind/react-native-web 조합에서
  `Cannot manually set... StyleSheet.setFlag(...)` 에러가 난다(2026-09-30 발견). 웹 타깃은
  현재 스토어 출시(Android 우선)와 무관해 이번 범위에서 고치지 않았다 — 나중에 웹 프리뷰가
  필요해지면 NativeWind v4 web 지원 버전을 다시 확인할 것.
